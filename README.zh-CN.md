# session-lessons

[English](README.md) | 简体中文

一个 Claude Code skill：把会话中的**教训**（约束未来行为的错误与规矩）沉淀进项目文档，让 AI 后续会话不再重复犯错。

## 解决什么问题

- AI 在一个项目里犯过的错，换个会话又犯一遍
- 教训散落在对话里，没有落进任何「生效位置」
- 复盘结论只停留在口头，下个会话全部丢失

## 整轮至多 1 次打断

| 模式 | 打断次数 | 怎么进入 |
|---|---|---|
| 标准模式（默认） | **1 次** | 说「沉淀教训」 |
| 直写模式 | **0 次** | 说「沉淀教训 直接写」「auto」 |
| 长期授权 | **长期 0 次** | 说一次「以后沉淀教训直接写」，授权行写入 AGENTS.md，此后该项目自动直写 |

标准模式的唯一一次打断是一张**合并清单**：台账条目、规矩正文改动、升级提议全部编在一起，回复「全」或编号即全部落盘，没有第二轮提问。所有开放决策（项目根目录、台账语言、指针文件、规矩落点、查重）由 AI 自行决定并以默认项形式出现在清单上——用户只做选择题，不做问答题。

**零厂商绑定**：skill 不使用任何厂商的内建记忆。所有价值都落在仓库文件——`LESSONS.md` 台账 + `AGENTS.md`/`CLAUDE.md` 指针与规矩——任何能读 AGENTS.md 的 agent（Claude Code、Codex、Cursor、Cline……）读到的是同一份沉淀。

## 工作流程

```
Ground（自定根目录/台账语言/查重索引——全自动）
    ↓
Inventory（候选 ≤7 条，逐条过「未来行为检验」）
    ↓
Checklist（唯一打断点）←──── 回复即落盘，无第二轮
    A 台账条目  B 规矩正文  C 升级提议
    ↓
Write（LESSONS.md + AGENTS.md/CLAUDE.md 指针 + 正文同步 + 升级）
    ↓
Report（一张改动表；直写模式附回滚清单）
```

## 条目格式

```markdown
### 2026-11-15｜发布正文不得残留 markdown 符号
- 触发：SH024 正文带 22 个反引号 + 20 个星号上线
- 根因：配文源文件是 markdown，回填时原样带入
- 规矩：配文一律纯文本
- 状态：已升级（→ preflight.js 硬拦截）
```

重复出现时在原条目末尾追加 `- 重复：YYYY-MM-DD`，不新建条目；累计 3 次提议升级为硬规则。

## 设计原则

1. **打断预算**：标准模式整轮只打断一次（合并清单），直写模式零打断；开放式决策全部由 AI 自决
2. **跨厂商**：不依赖任何 agent 的内建记忆；沉淀全部进仓库，任何读 AGENTS.md 的 agent 共享同一份
3. **未来行为检验**：候选教训必须能回答「它约束了未来什么行为」；功能清单、计划、流水账不达标
4. **单一真相源**：规矩正文写在它生效的文件（rules、主约束文件、脚本门禁），台账 `LESSONS.md` 只放一行指针——抄进文档的数字必漂移
5. **升级纪律**：同一教训累计 3 次 → 升级为硬规则，写入主约束文件，台账条目标「已升级」留指针
6. **台账轻薄**：只追加不改历史；重复教训不新建条目，只在原条目加一行「重复：日期」
7. **不越界**：只动本项目文件；指针至多一处；不代做 git commit

## 安装

**方式一：npx skills（推荐）**

```bash
npx skills add chenxuhl/session-lessons -g
```

**方式二：git clone + 拷贝**

```bash
git clone https://github.com/chenxuhl/session-lessons.git
mkdir -p ~/.claude/skills/session-lessons
cp session-lessons/SKILL.md ~/.claude/skills/session-lessons/SKILL.md
```

**方式三：手动复制** `SKILL.md` 到 `~/.claude/skills/session-lessons/SKILL.md`

## 使用

- 说「沉淀教训」「复盘教训」触发；建议时机：一次发布/重大变更完成后、事故复盘后
- 想跳过勾选：说「沉淀教训 直接写」，执行完给精确回滚清单
- 想长期免打扰：说一次「以后沉淀教训直接写」，授权写入 AGENTS.md，此后该项目自动直写
- 台账语言跟随项目现有文档语言（SKILL.md 本身为英文、面向 agent，不影响台账输出语言）

## FAQ

**怎么删掉不要的条目？** 台账只追加不改历史是纪律，不是锁——手动删即可。被硬规则完全覆盖的条目建议定期清理。

**直写模式会不会乱改？** 不会。它仍遵守全部边界：只追加不改历史、只动本项目文件、规矩正文落在生效文件、不代做 commit。每轮结束给逐文件回滚清单。

**支持其他厂商的 agent 吗？** 完全支持——这正是它和内建记忆方案的根本区别：skill 不使用任何厂商的记忆能力，沉淀全部落在仓库文件（`LESSONS.md` + `AGENTS.md`/`CLAUDE.md`），任何能读 AGENTS.md 的 agent——Claude Code、Codex、Cursor、Cline……——读到的是同一份价值。
